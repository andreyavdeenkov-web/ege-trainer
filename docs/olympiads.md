# Олимпиады — ядро банка заданий

Отдельное направление платформы для подготовки к олимпиадам по обществознанию: **олимпиадный практикум** (тематическая подготовка без привязки к конкретной олимпиаде) и **олимпиады** (первая — «Высшая проба»). Тренажёр ЕГЭ оно не затрагивает: свой код в `js/olymp/`, своё пространство имён `OLY`, будущие данные — в `data/olympiads/`.

Готовы **ядро** (каталог, типы заданий, проверка ответов, критерии оценивания, попытка), **пилотные данные** — официальная демоверсия «Высшей пробы» 2026/27, 9 класс, отборочный этап, I тур — и **интерфейс тематической тренировки** в `olympiad.html` (пробный тур — следующий этап).

## Принципы

- Банк организован по содержанию: **олимпиада → предмет → дисциплина → тема → задания**.
- **Задание не хранит класс, этап, тур и год.** Где оно встречалось (демоверсия, вариант прошлых лет, авторский сборник, номер вопроса, класс, этап, тур, год) — описывает **источник**. Одно задание может входить в несколько источников без дублирования.
- Реестр строит из источников производный **индекс появлений**; по нему работают фильтры класса, этапа, тура и года. Источник истины — ссылки из источников.
- `type` — способ взаимодействия, `scoring` — критерии оценивания. Баллы не выводятся из типа.
- **Критерии могут быть не определены** (`scoring: null`). Тогда ответ проверяется по ключу (верно / неверно), но баллы не начисляются. Правила оценивания не придумываются: в ядре нет ни одного правила, каждое добавляется только по официальным методическим рекомендациям или решению преподавателя.

## Каталог

```js
OLY.defineSubject({
  id: 'social', title: 'Обществознание',
  disciplines: [
    { id: 'SOC', title: 'Социология', topics: [
      { id: 'SOC-MOB', title: 'Социальная мобильность' }
    ] }
  ]
});

OLY.defineOlympiad({
  id: 'HP', title: 'Высшая проба',
  subjects: ['social'], classes: [9, 10, 11],
  stages: ['qualifying', 'final'],   // необязательно: этапы олимпиады
  rounds: [1, 2]
});
```

Каталог предмета общий для всех олимпиад. Темы добавляются по мере появления заданий; дисциплины и темы без заданий ученику не показываются.

## Задание

```js
OLY.addTasks([{
  id: 'HP-SOC-MOB-001',        // ОЛИМПИАДА-ДИСЦИПЛИНА-ТЕМА-НОМЕР, постоянный
  olympiad: 'HP', subject: 'social', discipline: 'SOC', topic: 'SOC-MOB',
  type: 'multiple-select',
  question: '…',
  options: [{ text: '…', correct: true, explanation: '…' }],
  explanation: '…',            // необязательно
  scoring: null,               // обязательно: null или критерии
  version: 1, retired: false   // необязательно
}]);
```

- ID не зависит от класса, тура, года и позиции в тренировке; начинается с `олимпиада-тема-`. Не меняется и не используется повторно; вместо удаления — `retired: true`.
- Поля `class`, `classes`, `round`, `year`, `source`, `sourceType` в задании запрещены — реестр отклонит такое задание. Этап (`stage`) тоже указывается только в источнике.

### Типы заданий

| type | Поля | Ответ ученика |
|---|---|---|
| `single-select` | `options: [{ text, correct, explanation? }]`, ровно один верный | `2` |
| `multiple-select` | `options`, хотя бы один верный | `[1, 3]` |
| `short-text` | `acceptedAnswers: [...]`, `normalize?: { yo: true }` | `'Эсхатология'` |
| `numeric` | `answer`, `tolerance?` (по умолчанию 0), `unit?` | `'12,5'` |
| `matching` | `items: [{ text, match, explanation? }]`, `options: [...]`, `oneToOne?`, `columns?` | `[2, 1, 3]` (А, Б, В…) |

**short-text.** Всегда нормализуются только технические различия: регистр, пробелы по краям, повторные пробелы. ё = е — только если в задании указано `normalize: { yo: true }`. Засчитываются лишь ответы из `acceptedAnswers` — их задаёт преподаватель.

**numeric.** Принимаются запятая и точка, знак «−», пробелы между разрядами. Нечисловой ввод — неверный ответ.

Новый тип добавляется через `OLY.types.register(name, { validateTask, emptyResponse, isEmpty, isComplete, cleanResponse, check, getCorrect, formatResponse })` — ядро менять не нужно.

## Источник

```js
OLY.addSource({
  id: 'HP-2026-27-DEMO-9-1',
  olympiad: 'HP', subject: 'social',
  kind: 'demo',                   // 'demo' | 'past' | 'author-set'
  year: '2026/27', classes: [9], round: 1,   // обязательны для demo и past
  stage: 'qualifying',            // обязателен для demo и past, если у олимпиады есть stages
  title: 'Демоверсия 2026/27 · 9 класс · отборочный этап · I тур',
  answersBasis: 'official',       // 'official' | 'author'
  playable: true,                 // можно пройти как пробный тур
  items: [
    { number: 1, taskId: 'HP-…-001' },
    { number: 2, taskId: 'HP-…-001', scoring: { … } }  // критерии этого варианта, если отличаются
  ]
});
```

Номера позиций идут подряд с 1. В пробный тур нельзя включить снятое с выдачи задание. `stage` проверяется по списку `stages` олимпиады; у олимпиады без этапов источник этап не указывает.

## Критерии оценивания

```js
scoring: null   // критерии неизвестны — только вердикт, без баллов

scoring: {
  maxPoints: 3,
  rule: 'имя-правила',            // из OLY.scoringRules
  params: { … },                  // необязательно
  basis: 'official',              // 'official' | 'author'
  ref: 'Методические рекомендации 2026/27, с. 4'   // обязательно для official
}
```

Если у позиции источника есть поле `scoring` (в том числе `null`), в пробном туре оно заменяет `task.scoring`.

Правило регистрируется так (сейчас правил нет):

```js
OLY.scoringRules.register('имя-правила', {
  supports: ['multiple-select'],             // или '*'
  validateParams: function (params) { return []; },
  score: function (result, maxPoints, params, task) { /* result = { verdict, details } */ }
});
```

## Запросы

```js
OLY.query({ olympiad: 'HP', subject: 'social', discipline: 'SOC', topic: 'SOC-MOB',
            class: 'all' | 9 | 10 | 11, stage: 'all' | 'qualifying' | 'final',
            round: 'all' | 1 | 2, year?, type? });
OLY.getAvailableDisciplines({ olympiad, subject, class?, stage?, round? });
OLY.getAvailableTopics({ olympiad, subject, discipline, class?, stage?, round? });
OLY.getPlayableSources({ olympiad, subject?, class?, stage?, round? });
OLY.getAppearances(taskId);  OLY.getTaskFacets(taskId);
```

Класс, этап, тур и год проверяются **по одному появлению**: фильтр «9 класс, II тур» находит задание, только если оно было во II туре 9 класса. Задание без источников находится только без этих фильтров. `query` возвращает задания в порядке регистрации; порядок пробного тура — `getSourceTaskIds(sourceId)` (по номерам источника).

## Попытка

```js
var A = OLY.attempt;
var p = A.createAttempt({ mode: 'practice', olympiad: 'HP', subject: 'social',
  settings: { discipline: 'SOC', topic: 'SOC-MOB', filters: { class: 'all', round: 'all' } },
  taskIds: [...] });
A.setResponse(p, taskId, value);   // черновик, можно менять
A.check(p, taskId);                // «Проверить»: ответ засчитан, дальше read-only
A.finish(p);

var m = A.createAttempt({ mode: 'mock', settings: { sourceId: 'HP-2026-27-DEMO-9-1' } });
A.setResponse(m, taskId, value);   // ответы меняются до завершения
A.finish(m);                       // оценка всех заданий сразу
A.summary(m);  // { total, correct, incorrect, skipped, points, maxPoints, scoredCount, unscoredCount }
```

- **practice** — свободная навигация и пропуск заданий; ответ засчитывается только по `check`.
- **mock** — набор и порядок из источника; до `finish` ничего не оценивается.
- `points` / `maxPoints` в итогах — только по заданиям с определёнными критериями; `unscoredCount` — сколько результатов без критериев.
- Попытка — JSON из примитивов и ID; точки расширения `OLY.attemptStore.onCheck` / `onFinish` пока ничего не делают.

## Интерфейс тематической тренировки

Запуск: `npm start` и `http://localhost:8080/olympiad.html` (или открыть файл напрямую). Страница ниоткуда не ссылается; тренажёр ЕГЭ не затронут.

Путь: **Олимпиады → Высшая проба → дисциплина → тема** (или «Все темы дисциплины») → настройка → тренировка → итоги. Предмет в интерфейсе не выбирается — он берётся из олимпиады (`subject` в данных сохранён). Класс не является уровнем каталога: задания разных классов по теме решаются вместе, класс, этап, тур — фильтры и подписи.

| Адрес | Экран |
|---|---|
| `#/` | олимпиады |
| `#/hp` | дисциплины олимпиады; режим «Пробный тур» — «скоро» |
| `#/hp/SOC` | темы дисциплины и «Все темы дисциплины» |
| `#/hp/SOC/SOC-CAR`, `#/hp/SOC/all` | фильтры и старт |
| `…/train`, `…/result` | тренировка и итоги (в памяти страницы; после перезагрузки — возврат к настройке) |

**Фильтры** — реестр `OLY.ui.filters`: класс и тур показываются всегда, этап, год, вид источника (`sourceKind`: демоверсии / прошлые годы / авторские) и тип задания — только когда в данных больше одного значения. У каждого значения — счётчик заданий с учётом остальных фильтров; значения без заданий неактивны. Новый фильтр: `OLY.ui.filters.register({ key, label, always?, values(ctx), format(value, ctx) })`, где `key` — поле `OLY.query`.

**Тренировка:** свободная навигация по номерам, пропуск, черновики сохраняются при переходах; «Проверить» фиксирует ответ, после этого задание только для чтения и показывается разбор. Под темой — строка источника («Официальная демоверсия „Высшей пробы“, 2026/27 · 9 класс · отборочный этап · I тур · № 2»). «Завершить» доступно всегда; выход и завершение с непроверенными заданиями — с подтверждением внутри страницы.

**Итоги:** «Верно: X из N», «Неверно», «Пропущено». Процент не показывается. Баллы — отдельным блоком и только если у проверенных заданий есть критерии оценивания. Разбор: все / с ошибками / пропущенные; «Решить пропущенные», «Повторить ошибки».

**Новые типы заданий:** `OLY.ui.views.register(type, { hint, render, renderReview, keyInput? })` (контракт — в `js/olymp/ui/views.js`). Задания типов без отрисовки в тренировку не попадают; тест проверяет, что у каждого типа из банка отрисовка есть.

## Олимпиадный практикум

Тематическая подготовка по дисциплинам, **не привязанная к конкретной олимпиаде**. «Высшая проба» — задания и тренировочные туры конкретной олимпиады; практикум — углублённая отработка понятий и различий по темам.

Путь: **Олимпиады → Олимпиадный практикум → дисциплина → (раздел) → тема → набор заданий.**

| Адрес | Экран |
|---|---|
| `#/pr` | дисциплины практикума: с заданиями — ссылки, без заданий — «скоро» |
| `#/pr/LAW` | темы дисциплины, сгруппированные по разделам («Теория права») |
| `#/pr/LAW/LAW-CPT` | старт темы: «24 задания · от базового уровня до олимпиадного», «Начать практикум» (без фильтров) |
| `…/train`, `…/result` | тренировка и итоги |

Практикум регистрируется как трек того же реестра — запросы, попытки, проверка и экраны общие:

```js
OLY.defineOlympiad({ id: 'PR', kind: 'practicum', title: 'Олимпиадный практикум',
  description: '…', subjects: ['social'] });   // без classes, rounds, stages
```

- У практикума нет классов, этапов, туров и **источников** (`addSource` отклоняется).
- Ученик не выбирает состав тренировки: пользовательских фильтров нет (`OLY.ui.filters.hasUserFilters` → `false`), всегда запускается вся тема в порядке `order`. Фильтры `level` и `type` остаются в реестре и в `OLY.query`.
- Порядок тренировки — **учебная последовательность из данных**: темы в порядке каталога, внутри темы — по `order`. В олимпиаде задания по-прежнему перемешиваются. «Повторить ошибки» и «Решить пропущенные» в практикуме сохраняют тот же порядок; выбор количества заданий скрыт.
- На главной практикум — отдельный блок «Тематическая подготовка» над списком олимпиад.

### Разделы и блоки в каталоге

```js
{ id: 'LAW', title: 'Право',
  sections: [{ id: 'theory', title: 'Теория права' }],          // необязательно
  topics: [{ id: 'LAW-CPT', title: 'Что такое право?', section: 'theory',
             blocks: [{ id: 'concept', title: 'Понятие права' }, …] }] }   // необязательно
```

Раздел группирует темы на экране дисциплины и входит в метку задания («Право · Теория права · Что такое право?»). Блоки — содержательные части темы в учебном порядке; название блока показывается над вопросом.

### Учебные поля задания

| Поле | Олимпиада | Практикум | Значение |
|---|---|---|---|
| `section` | необязательно | обязательно, если у темы есть раздел | совпадает с `topic.section` |
| `block` | необязательно | обязательно, если у темы есть блоки | id блока темы |
| `order` | необязательно | обязательно | место в учебной последовательности темы, целое от 1, уникально в теме трека |
| `level` | необязательно | обязательно | 1 — базовое понимание, 2 — применение, 3 — олимпиадный уровень |
| `tags` | необязательно | обязательно | проверяемые понятия, строки без повторов |
| `explanation` | необязательно | обязательно | общий разбор |
| `typicalMistake` | необязательно | необязательно | показывается **только после неверного ответа** (и в разборе нерешённых и ошибочных) |

`order` задаёт порядок явно, он не выводится из ID. Пояснение к каждому варианту (`options[].explanation`) и к каждой позиции соответствия (`items[].explanation`) показывается после проверки — для неверного выбора оно объясняет, в чём ошибка рассуждения.

### Повторное прохождение: attemptPolicy

Правила задаются в данных трека и проверяются реестром; ядро попытки (`OLY.attempt`) не меняется.

```js
OLY.defineOlympiad({ id: 'PR', kind: 'practicum', …,
  attemptPolicy: { allowRetake: false, allowRetryMistakes: false,
                   allowRetrySkipped: false, persistAttempts: true } });
OLY.getAttemptPolicy('HP');   // значения по умолчанию: всё разрешено, persistAttempts: false
```

| Настройка | По умолчанию | Практикум | Что разрешает |
|---|---|---|---|
| `allowRetake` | `true` | `false` | начать тему заново (и при начатой, и при завершённой попытке) |
| `allowRetryMistakes` | `true` | `false` | «Повторить ошибки» |
| `allowRetrySkipped` | `true` | `false` | «Решить пропущенные» |
| `persistAttempts` | `false` | `true` | сохранять попытку по теме в браузере и восстанавливать её после перезагрузки |

Логика — `js/olymp/ui/progress.js` (без DOM): `canStartNew`, `canRetry`, `topicState`, хранилище `createStore(OLY.ui.storage)`. Попытки хранятся в `localStorage` под ключом `olymp-trainer:attempts:v1` — словарь `{ 'PR/LAW/LAW-CPT': снимок попытки }`.

Практикум сейчас — одна попытка на тему: тренировка всегда по всей теме (без фильтров, выбора количества и «Все темы»); ответы сохраняются при каждом изменении; выход из тренировки без подтверждения — к ней можно вернуться («Продолжить тренировку»); после завершения тема открывается только для просмотра («Посмотреть результаты», «Пройдено: X из N верно»), кнопок новых попыток нет. Чтобы снова разрешить повторы, достаточно поменять `attemptPolicy`.

## Практикум «Норма права» — в разработке

Методические документы — `docs/drafts/pr-law-nrm-*.md`. Новые механики изолированы от `LAW-CPT` и пока подключены только к демонстрационной странице.

**Демонстрационная страница** `olympiad-demo.html`:
- собирается командой `node scripts/build-demo-page.js` из `olympiad.html` — вручную не редактируется, тест проверяет совпадение;
- добавляет к основной странице плашку «Демонстрация», стили `css/olymp-nrm.css`, общее ядро строк `js/olymp/types/nrm-rows.js`, типы `analysis-grid`, `text-markup`, `reasoning-check`, `formula-builder`, `short-answer`, `systematize`, `link-map` (три последних с общей основой `nrm-choice.js`), `argument-check`, `compound`, правило `components`, отрисовки `views/nrm-common.js`, `grid.js`, `markup.js`, `reasoning.js`, `formula.js`, `short.js`, `sort.js`, `links.js`, `arguments.js`, `compound.js` и данные `demo/law-nrm-demo.js`;
- демо-данные — отдельный трек `DEMO` с теми же правилами попыток, что у `PR`. Тексты норм помечены `verified: false`.

Основная страница `olympiad.html` эти файлы не подключает. Тест не допускает в публикуемом банке задания с несверенным текстом (`legal.verified !== true`) или с пометкой `demo: true`.

**Тип `analysis-grid` — классификационная карта** (`js/olymp/types/analysis-grid.js`):
- в строке ученик выбирает значение; при «спорно» — указывает, между какими видами спор;
- отмечает фрагменты нормативного текста как доказательство: основной нормы (`legal`, `role: 'main'`) и справочных норм (`role: 'reference'`).

**Баллы** — по трём компонентам:
- **K** — квалификация;
- **T** — работа с текстом нормы (доказательство в карте, разметка);
- **R** — логика рассуждения.

Частичные баллы:
- ½ — за допустимый, но более слабый ответ;
- ½ — за одну из двух спорящих квалификаций.

Равноправные ответы засчитываются полностью. Для каждого неверного варианта в данных обязательно объяснение ошибки. Правило оценивания `components` (`js/olymp/rules/components.js`, `basis: 'author'`) суммирует баллы элементов; `scoring.maxPoints` задания должен равняться их сумме.

**Тип `text-markup` — разметка структуры нормы** (`js/olymp/types/text-markup.js`):
- ученик выбирает инструмент палитры (`palette`: по умолчанию гипотеза, диспозиция, санкция) и нажимает фрагменты основной нормы;
- ключ `markup.key` задаёт элемент для каждого фрагмента; список элементов — спорная граница (засчитывается любая метка из списка), `null` — фрагмент не размечается;
- T — по 1 баллу за каждый элемент палитры; элемент, которого в тексте нет, засчитывается, только если им ничего не помечено («санкцию не дописывают»);
- строки выбора (`sections`) — как в классификационной карте, без доказательства.

**Тип `reasoning-check` — поиск ошибок в рассуждении** (`js/olymp/types/reasoning-check.js`):
- ученик отмечает ошибочные шаги и для каждого указывает происхождение (самостоятельная / только унаследована от шага N / унаследована + собственная) и содержательный тип Т1–Т6 по упорядоченному правилу;
- R: 2 — первый ошибочный шаг отмечен; 1 — отмечены остальные ошибочные шаги; 1 — не отмечен ни один верный; по каждому ошибочному шагу 1 — происхождение (с номером исходного шага) и 1 — тип, если он нужен;
- в данных обязательны объяснения: для верного шага (`wrong`), для пропущенного ошибочного (`missed`) и для типа, предшествующего ключевому по порядку (`typeWrong`).

**Типы третьего этапа:**
- `formula-builder` — конструктор формулировки: утверждение с пропусками (`template` с `{id}`), в каждом слоте 3–5 вариантов; по 1 баллу R за слот. Проверка данных не пропускает перекрёстные подсказки: правильный вариант слота не может встречаться в тексте утверждения или в вариантах других слотов;
- `short-answer` — краткий самостоятельный ответ: ссылка на статью (номер, часть, пункт, кодекс по списку синонимов; верная статья с неверной частью — ½), число цифрами или словами, термин из закрытого списка форм; по 1 баллу K. Под полем показывается, как программа распознала запись;
- `systematize` — систематизация: позиции распределяются по общим категориям (3–8, повторяются); по 1 баллу K за позицию;
- `link-map` — карта связей: вид связи для пар положений; виды связи с определениями задаются в условии, среди них обязателен «связи нет»; по 1 баллу K за пару, плюс строки-утверждения.

**Типы четвёртого этапа:**
- `argument-check` — оценка доводов: по каждому доводу два независимых решения — правильность (верен / неверен по фактам / неверен по праву) и связь с выводом при допущении, что довод верен (обосновывает / относится, но не обосновывает / опровергает / не относится). По 1 баллу R за каждое; ½ — довод верно признан неверным, но по другому основанию. Для спорной связи — равноправные ответы с обязательным описанием границ интерпретации;
- `compound` — составное задание по ситуации: части видов `choice` (строки, в том числе с доказательством из текстов, открытых к этой части), `short`, `arguments` открываются по очереди; тексты норм части появляются вместе с ней; зафиксированную часть изменить нельзя (проверяет и `cleanResponse`), поэтому поздние части не подсказывают ответы на ранние. «Проверить» доступна в последней части — для этого отрисовка может задать `canCheck(task, response)` (необязательный хук в `app.js`, существующие отрисовки его не задают).

**Ситуация рядом с вопросами** (общие для `analysis-grid` и `compound`): `situation` — абзацы общей ситуации; `definitions` — определения из условия `[{ term, text }]`; `row.context` — эпизод строки, печатается в её карточке при решении и в разборе; `layout: 'split'` — задаётся только там, где это помогает: на экране от 1100 px ситуация, определения и тексты норм закреплены в левой колонке, на узком экране кнопка «Ситуация и нормы» открывает их в диалоге. Блок `legal` с `fictional: true` — учебный документ условия (например, условный указ): официальной сверке не подлежит.

**Рабочий банк** (`work/law-nrm/*.js`, страница `olympiad-work.html`, трек PR, тема LAW-NRM) — задания практикума до публикации. Страница собирается тем же `scripts/build-demo-page.js`; основная страница его не подключает. Все задания — черновики (`draft: true`) со статусом сверки `verification.status` (`unconfirmed` — нормативные тексты не сверены; `no-legal-text` — текстов нет). Тест `tests/olymp-nrm-work.test.js` не допускает черновики и несверенные тексты в публикуемый банк и проверяет, что форма вариантов не подсказывает ответ (длина правильного варианта; перемешанный показ строк с `shuffle: true`).

**Вердикт `partial` («частично»)** выдают только новые типы:
- в полосе номеров — жёлтый цвет;
- в итогах — строка «Частично» и баллы по компонентам.

Поле `partial` в итогах попытки появляется, только если в ней есть такие результаты. Поэтому итоги попыток `LAW-CPT` и олимпиад не меняются.

**Защитные тесты** `tests/olymp-law-cpt-guard.test.js` проверяют по эталонам из `tests/fixtures/`:
- задания `LAW-CPT`;
- проверку ответов;
- правила попыток;
- восстановление сохранённых попыток;
- порядок скриптов `olympiad.html`.
