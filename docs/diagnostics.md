# Диагностика по теме (этап 1)

Модуль `js/diagnostics.js` строит диагностический отчёт по работам ученика: что получается, что стоит повторить и какие задания решить дальше. Разметка заданий хранится отдельно: `data/diagnostics/<тема>.js`. Пилотная тема — «Типы обществ» (OBS-TYP): 3 практикума, 55 заданий, 302 позиции.

Этап 1 — это только чистые функции и данные. К страницам ничего не подключено. Баллы, немедленная обратная связь в тренировочных практикумах и отложенная в итоговой работе не меняются: их по-прежнему считают `js/scoring.js`, `js/attempt.js` и `js/final-session.js`.

## Принципы

- Выводы делаются только из наблюдений: ответ, ключ и разметка позиции.
- Коды описывают, что произошло в ответе, а не предполагаемую причину. Предположение о причине допустимо только в тексте разбора, со словами «возможно» или «похоже».
- Освоение подтверждается только независимыми наблюдениями. Не считаются:
  - повтор знакомого задания;
  - верный ответ после разбора ошибки по тому же блоку понятий в той же тренировке;
  - почти тождественные формулировки (семейство учитывается как одно наблюдение).
- Нормативные идеалы подтверждают знание ценностных ориентаций типа, а не его реальной практики.
- Контекстные индикаторы говорят о применении теории к ситуации, а не о знании типа общества.
- Пороги экспериментальные (`THRESHOLDS`). Их нужно проверить на данных учеников.

## Разметка

Задание: `op` — операция (`R` распознавание, `M` сопоставление, `A` применение к ситуации); `target` — тип, о котором задание; `scope` — сферы, которыми ограничено условие; `trans` — задание о переходе между типами.

Позиция — строка `ТИП.СФЕРА.понятие[модификаторы]`, например `I.E.capital+fact@P`.

| Часть | Значения |
|---|---|
| ТИП | `T`, `I`, `P`; `U` — признак любого общества; `X` — не признак типа (ошибка формулировки или направления), у контекстного индикатора — тип не определяется |
| СФЕРА | `E` экономика, `S` социальная структура, `P` политическая жизнь, `D` духовная жизнь, `N` отношение к природе |
| Категория | по умолчанию устойчивый признак; `!t` историческая тенденция; `!n` нормативный идеал; `!d` дискуссионная характеристика |
| `@T` `@I` `@P` | неверное суждение приписывает признак этому типу |
| `+fact` `+abs` `+cause` `+trans` | фактор производства или ведущая сфера; абсолютная формулировка; ложная причинность; направление изменения |
| `+conc=<пара>` | названная пара смешиваемых понятий |
| `+ctx` | контекстно зависимый индикатор |
| `+inst` | конкретное проявление тенденции |

Категорию определяет то, что подтверждает ответ ученика, а не слово в формулировке. «Возрастает роль знаний как фактора производства» — устойчивый признак (ведущий фактор производства). «Возрастает значение непрерывного образования» — тенденция.

**Семейства** — почти тождественные формулировки одной смысловой силы, проверяющие одно знание. «Возрастает роль знаний» и «знания — основной фактор производства» — разные семейства. Неверное суждение и прямая формулировка одного признака могут входить в одно семейство: независимость не завышается, а вид подтверждения (узнавание или отклонение ошибочного приписывания) и проверенная пара типов сохраняются в наблюдении.

`EGE.diagnostics.checkTopic(topicId)` сверяет разметку с ключами, картой темы и семействами. Тест требует, чтобы расхождений не было.

## Наблюдения и коды

У каждой позиции ответа есть исход:
- `ok`;
- `accepted` — принят чужой признак;
- `rejected` — не узнан свой;
- `mismatch` — в соответствии выбран другой тип.

Ещё у позиции есть вид подтверждения: `recognition` или `rejection` с полем `contrast` — какая пара типов проверялась.

Основной код ошибки выбирается по приоритету:

1. КОНТ — контекстный индикатор;
2. НЕУЗН — признак не узнан;
3. УНИВ;
4. ПОНЯТ — пара типов становится дополнительным кодом;
5. пара типов Т/И, И/П, Т/П;
6. ФОРМ, ПРИЧ, ПЕР — для позиций, которые не являются признаком типа;
7. СФЕРА;
8. НЕКЛ — в размеченной теме не встречается, это проверяет тест.

Аспекты ФАКТ, ПЕР, СИТ, ДИСК добавляются к ошибке и с кодами не конкурируют.

## Элементы и статусы

Элементы отчёта:
- `cell:T.E` — клетка «тип × сфера»: устойчивые признаки и тенденции;
- `norm:T` — ценностные ориентации и идеалы типа;
- `skill:ПЕР`, `skill:УНИВ`, `skill:СИТ`, `skill:ФОРМ` — умения.

Контекстные индикаторы в клетки не попадают.

Статус проверяется по порядку:

1. **не проверяется** — в банке нет позиций по элементу;
2. **повторяющееся затруднение** — ошибки в двух и более разных заданиях одной работы или в двух работах подряд, и ошибка есть в последней работе;
3. **недостаточно данных** — меньше 3 семейств или меньше 2 заданий («мало независимых наблюдений»), либо ошибок больше допустимого («результаты неоднородны»: ни одной при менее чем 5 семействах, одна — при 5 и более);
4. **получается устойчиво** — выполнены все условия:
   - две работы, одна из них итоговая;
   - не меньше 4 семейств и 4 заданий;
   - в последней работе ошибок нет;
   - для клетки — два вида операций и хотя бы одно семейство устойчивых признаков (только на тенденциях «устойчиво» не ставится);
5. **получается — предварительно** — во всех остальных случаях.

## «Что стоит повторить» и маршрут

Пункт появляется, только если ошибки одной группы есть в двух и более разных заданиях одной работы. Группа образуется так:
- код и сфера — для пар типов;
- клетка — для НЕУЗН;
- пара понятий — для ПОНЯТ.

Отдельно проверяются понятия — если их ошибки не вошли целиком в одну группу.

**Контекстные индикаторы** дают один пункт КОНТ — «применение признаков к ситуации». Он идёт после пунктов о признаках типов, если заданий столько же. Поле `typeErrorsInTargets` показывает, были ли в этой работе ошибки по признакам искомых типов. Фразу «по типовым признакам этих типов ошибок нет» интерфейс выводит, только если это поле равно `false`.

**Маршрут** — до трёх ещё не решённых заданий темы, в которых по разметке есть позиции той же группы. Если таких заданий нет, маршрут пустой: это место для режима «Работа над ошибками» (следующие этапы).

## Использование

```js
var report = EGE.diagnostics.buildReport([
  { practicumId: 'OBS-TYP-P01', answers: { 'OBS-TYP-026': [3, 5] /* … */ } },
  { practicumId: 'OBS-TYP-F01', answers: { /* … */ } }
]);
// report.statuses, report.repeat (с report.repeat[i].drills), report.groups, report.familiarProgress
```

Работы передаются в порядке прохождения. `answers` — в том же формате, что в попытке: номера выбранных вариантов или номера по строкам А–Д.

Тесты: `tests/diagnostics.test.js` (наборы A, B, C и граничные случаи из спецификации) и `tests/diagnostics-markup.test.js` (разметка, подписи, согласованные решения).
