# LAW-NKL · Проект кнопки «Начать заново»

**Статус:** проект для согласования. **Ничего не внедрено.**
Ветка `claude/law-nrm-simple`, 13.10.2026.

## Как сейчас

- Политика попыток задаётся для всего трека практикума `PR`, а не для отдельной темы. Поле `attemptPolicy` в `data/olympiads/practicum/practicum.js`:
  - `allowRetake: false`;
  - `allowRetryMistakes: false`;
  - `allowRetrySkipped: false`;
  - `persistAttempts: true`.
- Попытка каждой темы хранится в `localStorage` под ключом `olymp-trainer:attempts:v1`. Это словарь вида `{ 'PR/LAW/LAW-NKL': снимок, 'PR/LAW/LAW-CPT': снимок, … }` (модуль `js/olymp/ui/progress.js`).
- Начать новую попытку можно только если попытки нет или разрешён повтор: `canStartNew(policy, attempt) = topicState(attempt) === 'new' || policy.allowRetake`. После завершения тема открывается только для просмотра.

Если просто включить `allowRetake: true`, повторы станут доступны во всём практикуме — в том числе в LAW-CPT и LAW-NRM. Поэтому нужна настройка на уровне темы.

## Предлагаемое решение

### 1. Данные

Добавить в тему LAW-NKL необязательную настройку `allowRestart` (как `collapsedFeedback`, `normAsHeading`):

```js
{ id: 'LAW-NKL', …, allowRestart: true }
```

Реестр (`js/olymp/registry.js`) проверяет её как `true` / `false`. Другие темы ведут себя по-прежнему.

### 2. Хранилище

В `createStore` (`progress.js`) добавить метод `remove(scope)`. Он удаляет из словаря **только** запись `PR/LAW/LAW-NKL`; попытки других тем остаются нетронутыми. Ошибка хранилища (например, приватный режим) обрабатывается молча, как в `save`.

### 3. Правило

`canStartNew(policy, attempt, topic)` возвращает `true`, если попытки нет, если `policy.allowRetake` или если `topic.allowRestart`. Правила `allowRetryMistakes` и `allowRetrySkipped` не меняются: «Повторить ошибки» и «Решить пропущенные» остаются выключенными.

### 4. Интерфейс

На стартовом экране темы под основной кнопкой («Продолжить тренировку» или «Посмотреть результаты») появляется второстепенная кнопка **«Начать заново»**. По желанию её можно продублировать на итоговом экране рядом с «К темам».

Нажатие показывает **существующую панель подтверждения** (та же, что при «Завершить»):

> Все ответы и баллы этой темы будут удалены, и тренажёр начнётся с первого задания. Начать заново?
> [Отмена] [Начать заново]

После подтверждения:
1. вызывается `store.remove('PR/LAW/LAW-NKL')`, и попытка в памяти страницы сбрасывается;
2. открывается стартовый экран с кнопкой «Начать практикум»; порядок заданий и перемешивание вариантов прежние, так как они стабильные.

Текст о политике попыток для этой темы меняется. Вместо «Повторное прохождение темы пока недоступно…» и предупреждения «Тему можно пройти один раз…» будет: «Тему можно пройти заново: прежние ответы при этом удаляются».

### 5. Тесты

- Реестр: `allowRestart` принимается только как `true` / `false`.
- `progress`: `remove` удаляет одну область и не трогает соседние (`PR/LAW/LAW-CPT` остаётся).
- `canStartNew`: для LAW-NKL — `true` при завершённой попытке; для LAW-CPT — `false`, как раньше.
- Защитные тесты LAW-CPT (снимки попыток, политика трека) — без изменений.
- Браузер: пройти несколько заданий → «Начать заново» → «Отмена» (ничего не изменилось) → «Начать заново» → подтвердить → «Проверено: 0 из 20», попытка LAW-CPT в хранилище сохранилась.

**Объём:** около 40–60 строк кода в `registry.js`, `progress.js` и `app.js`, одна строка в каталоге, 4–5 тестов. Дизайн и стили не меняются: кнопка в существующем стиле `btn btn--ghost`.

## Вопросы для решения

1. **Когда показывать кнопку:** только после завершения попытки или и во время прохождения? Рекомендую в обоих случаях, но всегда с подтверждением.
2. **Нужна ли кнопка на итоговом экране** или достаточно стартового?
3. **Педагогика.** Повтор снимает ограничение «одна попытка». Если результат первой попытки важен учителю, его стоит сохранять отдельно. Сейчас результаты хранятся только в браузере ученика, и учитель их не видит, поэтому на учёт результатов кнопка не влияет.
